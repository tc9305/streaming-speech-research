# SimulST／StreamST 研究選題討論稿

> 本稿聚焦研究問題與選題，不做顯卡、訓練時數或部署可行性的推算。

## 研究定位

本研究希望利用既有 Speech LLM，改善即時語音翻譯的**翻譯品質、實際延遲、輸出穩定性與計算成本之間的取捨**。

核心問題可拆成三個決策：

1. **何時呼叫模型？** 新收到的語音是否值得啟動一次翻譯？
2. **何時定稿？** 目前翻譯是否可靠到可以不可撤回地輸出？
3. **何時使用術語提示？** 目前聲學證據是否足以支持加入或採用某個術語？

這些問題已有相關研究。因此，我們的目標是找出**既有策略在哪些條件下失效，以及新增機制能否帶來可歸因、可重現的改善**。

## 一、當前領域的核心痛點

| 核心痛點 | 具體問題 | 目前證據與尚待驗證之處 |
|---|---|---|
| **1. 呼叫時機與計算負擔難以兼顧** | 固定短週期可能反覆處理資訊增量很少的語音；拉長週期又可能延後本來已能翻譯的內容。VAD 提供聲學停頓訊號，但不直接代表翻譯所需資訊已足夠。 | 既有系統採用 VAD 與時間限制等策略；更細緻的控制是否能降低「包含計算時間的實際延遲」，仍需同條件實驗。 |
| **2. 部分語音下的翻譯尚未穩定，卻必須決定是否定稿** | 新增上下文可能改變譯文內容或語序。太早定稿會留下錯誤，太晚則失去即時性。 | NeMo 曾觀察到 En→Zh 重排序拖慢共同前綴穩定。已有信心與 commit 研究，缺口不能寫成「沒有人研究何時輸出」。 |
| **3. 輕量串流訊號與大型翻譯模型尚有整合取捨** | Cascade 的 ASR 文字中介可能遺失資訊；直接使用語音的模型則仍需要有效的串流控制。輕量 ASR 能否只提供控制訊號，是值得測試的設計。 | 不傳遞 ASR 文字，不代表完全沒有錯誤傳遞；錯誤仍可能透過切分、等待或觸發決策影響翻譯。 |
| **4. 術語提示的幫助與誤導同時存在** | 提示可能改善罕見詞翻譯，也可能讓模型在證據不足時採用錯誤術語。過嚴的門檻則可能漏掉真正出現的術語。 | RASST 已處理術語使用與時機。研究機會在於找出其仍未解決的情境，驗證額外聲學證據是否有效。 |
| **5. 長篇翻譯需要在有限記憶下維持一致性** | 有限上下文可能使先前術語、人物指涉或翻譯選擇無法持續影響後文。 | 有界快取是既有設計；「被移除的資訊造成哪些具體錯誤」仍需診斷，不能直接當成已證明的普遍失敗。 |

其中，**內部草稿改寫、使用者看到的字幕閃爍、不可撤回的錯誤定稿，是三種不同現象**，後續應分開定義與評估。

文獻依據：[Test-Time Adaptation](https://aclanthology.org/2026.iwslt-1.27.pdf)、[NeMo](https://aclanthology.org/2026.iwslt-1.23.pdf)、[RASST](https://arxiv.org/html/2601.22777)、[InfiniSST](https://arxiv.org/html/2503.02969)。

## 二、戰略避坑指南：本研究明確不做什麼，以及為什麼

以下「不做」是**本研究的範圍決策**，不代表這些方向在學術上沒有價值。

| 明確不做 | 原因 | 保留的合理做法 |
|---|---|---|
| **不以「Zipformer＋LLM 串接成功」作為主要貢獻** | 已有 transducer 與 LLM 結合的系統。元件組合本身不足以回答新的研究問題。 | 將組合作為平台，研究控制訊號何時有效、何時失效，以及為什麼。 |
| **不以通用即時翻譯 demo 作為論文核心** | Demo 能展示功能，卻無法單獨證明品質、延遲或穩定性的改善來自所提方法。 | Demo 用於展示研究結果，主要貢獻由對照實驗支持。 |
| **不從頭預訓練大型模型，也不將大型全參數訓練或大規模 RL 設為研究起點** | 初期應先確認問題存在、控制訊號有效，以及與既有研究的差異。大型訓練會增加驗證成本與歸因困難。 | 先凍結骨幹；若證據顯示必要，可加入小型校準器或有限的參數高效微調。 |
| **不一次同時改呼叫、定稿、檢索與記憶** | 即使整體變好，也難以辨認是哪個機制造成改善；失敗時同樣難以定位。 | 先選一個主問題，其他模組固定；主方法有效後再研究組合。 |
| **不只報 BLEU 或平均延遲** | 平均值可能掩蓋漏譯、長時間沒有更新、末尾積壓及錯誤定稿。 | 同時檢查品質、實際延遲、尾端表現與方向專屬指標。 |
| **不把未來資訊帶入線上決策，也不只挑有利案例** | 這會使方法在真正串流情境下無法成立，或高估效益。 | 未來語音只可用於離線標籤與診斷；測試資料與調參資料分離，保留失敗案例。 |

**長篇語意記憶管理暫不列為第四條主線。** 先把長篇作為測試條件；若能明確觀察到跨視窗資訊遺失，再評估是否值得獨立研究。

## 三、給老師挑選的三大主力研究方向

### 方向 A：利用輕量串流訊號控制 Speech LLM 的呼叫時機

**研究問題：在維持翻譯品質與輸出完整性的條件下，能否減少不必要的模型呼叫，並降低實際延遲？**

讓 streaming transducer 持續處理音訊，提供 blank、emission、辨識前綴變化等候選訊號；控制器據此決定是否呼叫 Speech LLM，翻譯內容仍由語音輸入產生。

初期採用簡單規則，搭配最大等待時間與結尾強制處理，避免「少呼叫」其實只是延後或漏掉輸出。

- **可能貢獻：** 找到比固定週期或 hybrid VAD 更有效的呼叫策略，並解釋哪些訊號真正有用。
- **必要比較：** 同一翻譯模型下的固定週期、hybrid VAD，以及相近呼叫次數的控制策略。
- **主要風險：** Transducer 訊號可能沒有超過 VAD 的資訊；新增控制成本也可能抵銷節省。
- **停止條件：** 匹配品質與呼叫預算後優勢消失，或收益僅來自延後輸出。

**一句話提案：讓翻譯模型在有必要時才執行，驗證輕量聲學訊號是否比時間與停頓更能判斷呼叫時機。**

### 方向 B：部分語音下的定稿風險估計與校準

**研究問題：能否利用當下可取得的訊號，估計現在定稿會出錯的風險，改善可靠性與等待時間的取捨？**

蒐集不同語音前綴下的翻譯軌跡，觀察新增語音後哪些內容需要修正。利用信心、候選差距、跨次輸出一致性等訊號，建立門檻或小型風險校準器。

首先必須區分：後續改寫是修正語意錯誤，還是只是同義改寫。不能把所有字串變動都標成不安全。

- **可能貢獻：** 在明確情境中改善風險校準，例如長篇或跨領域條件，並驗證品質與定稿延遲的取捨。
- **必要比較：** 原生策略、適用的 wait-k、LocalAgreement，以及未校準的信心門檻。
- **主要風險：** 標籤建構較難，且已有高度相近研究，必須先確認差異。
- **停止條件：** 無法可靠定義錯誤定稿，或校準方法對簡單門檻沒有額外價值。

**一句話提案：讓系統知道哪些內容可以放心定稿，並量化為了降低錯誤需要多等多久。**

相關研究已有 [DiG-SST](https://ojs.aaai.org/index.php/AAAI/article/view/29733) 與 [Learning When to Commit from Partial Speech](https://arxiv.org/html/2610.02612)，不能將「使用不確定性決定輸出」本身作為新穎性。

### 方向 C：以聲學證據控制術語提示的使用時機

**研究問題：加入額外的串流聲學證據，能否減少不適當的術語使用，同時保留真正術語的翻譯能力？**

在術語檢索後加入證據檢查：目前語音是否支持該候選術語？證據不足時先暫緩，足夠時才允許提示或使用。

需區分兩個時機：**來源術語已有足夠證據**，不等於**目標譯文已適合定稿**。

- **可能貢獻：** 在錯誤候選、相似發音與術語尚未完整出現時，改善術語精確率、召回率及使用時機。
- **必要比較：** 無術語提示、相同檢索器但無額外門控、僅依檢索分數門檻，以及可重現的相關方法。
- **主要風險：** 罕見術語可能正是 transducer 最不可靠的部分；降低誤插的同時可能增加漏詞。
- **停止條件：** 改善只能靠全面抑制術語提示，或收益無法超過簡單檢索門檻。

**一句話提案：避免術語提示超前於語音證據，同時確保真正出現的術語仍能及時被翻對。**

[RASST](https://arxiv.org/html/2601.22777) 已研究術語使用及時機，因此必須證明新增證據的額外價值。

## 四、三個方向的具體對照表

以下是選題判斷，不是實驗結果或錄取機率預測。

| 比較面向 | A：呼叫時機控制 | B：定稿風險校準 | C：術語證據門控 |
|---|---|---|---|
| 主要改善目標 | 計算成本與實際延遲 | 錯誤定稿與等待時間 | 術語正確率與誤插 |
| 決策位置 | 呼叫翻譯模型之前 | 草稿產生之後、定稿之前 | 術語提示或採用之前 |
| Zipformer 角色 | 主要候選訊號來源 | 可選輔助訊號 | 術語證據的候選來源 |
| 初期是否需新增訓練 | 規則版本可不需要 | 門檻版本可不需要；校準器可能需要 | 規則版本可不需要；另需確認檢索器來源 |
| 主要資料需求 | 串流音訊、翻譯參考及時間紀錄 | 多前綴輸出軌跡、錯誤定稿標籤 | 術語表、出現位置與干擾候選 |
| 主要評估 | 品質、包含計算的延遲、呼叫數、總成本 | 品質、錯誤定稿率、定稿延遲、風險校準 | 術語 precision／recall、誤插、過早使用、延遲 |
| 關鍵消融 | 拿掉各訊號；匹配呼叫預算 | 原始信心與校準後比較；拆分特徵 | 相同檢索結果下有無聲學門控 |
| 最大研究風險 | 只減少呼叫，沒有實際收益 | 與近作重疊、標籤不可靠 | 少誤插但漏掉真正術語 |
| 初期執行判斷 | 較容易先建立可歸因的對照 | 應先解決定義與文獻差異 | 應先確認資料與標註條件 |

**建議優先以 A 做第一輪 pilot。** 它較容易固定翻譯骨幹，只改控制策略，快速判斷訊號是否有價值。

若老師更重視決策可靠性與方法分析，可選 B；若實際應用明確鎖定專業演講或 EMI，且已有術語資源，則 C 更貼近場景。三者是選項，初期只選一條主線。

## 五、近期執行計畫與需要拍板的事項

### 第一週：定義問題，建立可信的比較起點

1. 選定主方向、主語言對與輸出形式：只顯示定稿，或同時顯示可修訂草稿。
2. 選一個可重現的翻譯骨幹，先完成基本串流流程。
3. 固定資料切分與評分方式，建立固定週期及 hybrid VAD 等適用 baseline。
4. 保存音訊到達、模型呼叫、草稿更新、可見字幕更新與定稿時間。
5. 整理最接近的相關研究，明確寫出本案多回答哪一個問題。

**第一週交付：** 一份實驗設定、一組 baseline 結果，以及代表性失敗案例。

### 第二週：只驗證一個核心假說

- **選 A：** 比較 transducer 訊號與 VAD，確認收益是否超過單純減少呼叫。
- **選 B：** 建立小批診斷軌跡，確認候選訊號能否辨認真正不安全的定稿。
- **選 C：** 建立術語正例與干擾案例，檢查門控是否同時維持召回與降低誤插。

**第二週交付：** 方法與 baseline 的取捨曲線、必要消融、失敗原因，以及繼續／修正／停止的建議。

此時不預先承諾固定百分比的改善。先訂定品質與完整性底線，再根據 baseline 波動設定有意義的成功門檻。只有多等、少輸出或少使用術語所換來的表面改善，不算成功。

### 第三至四週：在 pilot 有效後擴大驗證

加入不同演講、較長音訊與困難案例，檢查效果是否只存在於調參資料。主效果穩定後，再考慮第二模型或第二語言對，並形成論文主張。

| 決策 | 建議起點 |
|---|---|
| 第一階段主問題 | A：呼叫時機；B、C 保留為替代選項 |
| 主語言對 | En→Zh 作為候選，先確認所選骨幹與資料支援 |
